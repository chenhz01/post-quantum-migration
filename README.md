# 后量子密码迁移 · 十件研究笔记

一套长期跟踪后量子密码迁移写下的独立研究笔记：从 Shor 算法的威胁模型出发，经标准家谱、混合密钥交换、密码清单、协商可观测性、敏捷性与监管时钟，落到一人公司能执行的动作清单与季度记分卡——每条结论都带边界数、来源等级与证伪条件。

## 两性费曼：怎么读这套笔记

每件笔记的正文之前有两块固定结构，两层互相制约：

- **性一（12 岁也能懂）**——这是什么（生活比喻 + 一句「哪里不像」）/ 与我何干（只落在**省钱、赚钱、避险、暂无**四选一）/ 我该怎么办（一个 ≤2 小时、今天就能开始的具体动作）。判据：不允许出现未解释的术语；若 12 岁的人读完会问「所以呢」，就是「与我何干」没写清。
- **性二（同行可验证）**——机制（推到基座）/ 边界数（数字 + 来源等级裸写）/ 反例（什么证据能推翻这条结论）/ 可复现（最小验证路径）。判据：不允许出现无法验证的断言；给不出数，性一就只是好听。

只过一层不算懂：缺性一是自嗨，缺性二是空话。完整协议见 [FEYNMAN.md](./FEYNMAN.md)。

两层读完再看正文。正文保留原有结构：「为什么这条路线被低估」→「第一性原理拆解」→「技术机制与关键事实」→「反例与证伪条件」→「对善伦业务的迁移点」→「最小下一步动作（≤2 小时）」。

## 这套笔记不主张什么

以下条目是本套笔记的证伪条件汇总。任何一条成立，对应笔记的结论就要改写；被推翻是预期内的正常结果，不是失败。

1. **CRQC 到达时间仍有争议。** 本套笔记不主张密码学相关量子计算机会在某一年到达。01/02/08 号给出急迫性，依据是替换周期（全球银行替换全套密码 routinely 需要十年以上）与数据寿命（2026 外泄的数据 2032 年仍敏感），不是硬件时间表。证伪条件：出现可信的物理证明——容错量子计算机不可实现或经济上永不可行——则威胁模型作废，迁移降级为纯保险行为。
2. **部署≠就绪：TLS 协商回退的可见性缺口。** 本套笔记不主张「配置里开了混合组」等于「流量里用上了混合组」。06 号的全部内容就是这个落差：一端不支持即回退古典密钥交换，而两侧面板可能都显示已启用。证伪/关闭条件：两端全自控且强制只用后量子时缺口消失（但面向全球浏览器与合作方服务端不可行）；或监控显示混合组占比接近 100% 且连续数月稳定。
3. **不主张格密码长期稳健。** 03 号的选型依据不是「格一定安全」，而是命门分散：格路径承担效率，哈希路径只押注抗碰撞性。证伪条件：格密码被找到高效经典攻击或更优量子攻击——被证伪的是「选格」这个决定，不是「迁移」这个方向；攻击只会改变迁移目标，不会取消迁移。
4. **不主张 ICP/HER/CARI 三个数能单独证明安全。** 09 号的三个阈值（98% / 60% / 85%）建立在估算分母与统计口径之上。证伪条件：ICP 的分母「总估算资产」未留档、估算方法未独立于执行人，则该指标不采信；HER 的统计口径若与 06 号的协商观测不一致，数字即为装饰；三指标全绿仍可能裸奔——回退流量未观测、影子资产未入册、供应商黑盒未拆。
5. **不主张 NIST IR 8547 的 2030/2035 是既成事实。** 它是草案日期，不是生效条款。证伪条件：正式版推迟或柔化会改变节奏，但不改变弃用方向；且标准一旦进入采购合同，惯性独立于监管存续——合同不会因为草案推迟而自动失效。
6. **不主张 QKD 是 PQC 的替代品。** 10 号列出三条未解决的问题：认证、互操作、成本与 KMS 集成。证伪条件：出现同时解决这三项且有独立第三方测评的工程方案，此条需重写。
7. **不主张敏捷性投入越多越好。** 07 号给出边界：若业务线生命周期短于算法换代周期，敏捷投入收不回来；抽象门面会把分散的重构风险换成集中的运行风险（一次配置错误放大为全站事故），对策是变更审计与灰度发布，不是放弃抽象。
8. **不主张一人公司必须立刻立项目。** 10 号给出反例：若清点后密码面确实极小（全部流量走一个已默认启用混合密钥交换的现代托管服务、自持仅一张短寿证书），激进迁移的边际收益低于投入，正确动作是维持监测而非上项目——且这个判断以先完成清点为前提，不成立于清点之前。

## 证据纪律

- **数字必指源。** 每件笔记的边界数后裸写来源等级：[一手] = 标准原文、官方指南、RFC/草案、原始论文、自行实测；[二手] = 综述、报道、转述、行业框架；[推算] = 由已知数推导，推导过程写在正文。
- **无源数字不进入对外文本。** 拿不到来源的数字，要么删掉，要么降级为假设并在正文标注。
- **区分发布状态。** 已发布 RFC 与变动中的 Internet Draft 不等价（04/06/10 号）：生产系统用 RFC，Draft 上的部署不计就绪。草案（如 NIST IR 8547）与正式版分开标注。
- **事实与看法分开。** 正文中以「事实包」标注的是外部来源，以「推算」标注的是本套笔记自己的推论，两者不混写在同一句里。
- **每条结论必带反例。** 写不出反例的判断不写进正文；反例要具体到「什么证据能推翻它」，而不是「也许会错」。
- **修订留痕。** 指标口径、定义、阈值一旦变更，必须显式标注并重述历史，否则前后两期不可比。
- **不扩张事实边界。** 修订时只补来源与数字，不把事实包之外的内容写进结论。
- **隐私与称谓。** 全文只保留称谓「善伦」，不出现真实姓名、邮箱与任何身份标识。
